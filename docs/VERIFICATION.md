# Отчёт о проверке

Дата: 30 октября 2026. Проверены исходники, готовый исполняемый JAR и реальные HTTP-запросы локального деморежима.

## Исправление подключения встроенного сервера

В присланном пользователем логе IDEA JDK и Servlet API уже присутствуют, но в classpath нет `spring-boot-tomcat` и `tomcat-embed-core`; Spring останавливается без `ServletWebServerFactory`. В POM старый `spring-boot-starter-web` заменён на `spring-boot-starter-webmvc`; `spring-boot-starter-tomcat` объявлен явно. Версии задаёт Spring Boot 4.1.1.

После этой правки повторно выполнен `clean verify`: **45 тестов, 0 failures, 0 errors, 0 skipped**. Затем приложение запущено через `spring-boot:run` с `useTestClasspath=false` и профилем `demo`. Лог подтверждает запуск main-класса из `target/classes` и Tomcat на 8087. Выполнены **26 HTTP-проверок** Swagger, авторизации, экзамена и PDF. Это проверяет обычный runtime classpath, а не только загрузчик готового JAR.

Новый JAR пересобран; проверены его CRC, встроенный POM, наличие Spring Boot Tomcat/MVC и `tomcat-embed-core`, отсутствие дублирующего Servlet API JAR. В этом обновлении новый JAR отдельно не запускался: HTTP проверялся запуском из `target/classes`. Ранее выполненные проверки PostgreSQL и запуск предыдущего JAR сохраняются как история ниже. Выполнение в самой Windows/IDEA пользователя не проверялось. В README добавлены настройки Project/Module SDK и Active profiles: demo.

## Предыдущая проверка явного подключения Servlet API

После сообщения об ошибке `cannot access jakarta.servlet.Filter` в IntelliJ IDEA в POM добавлена прямая зависимость `jakarta.servlet-api:6.1.0` со scope `provided`. Версию выбирает Spring Boot. Отдельный API JAR исключён из упаковки Spring Boot; во время работы классы предоставляет `tomcat-embed-core:11.0.24`.

Повторно выполнены `clean verify`: **45 тестов**, без ошибок и пропусков. В classpath каждого набора тестов подтверждено присутствие новой API-зависимости. Пересобранный JAR запущен и прошёл **26 HTTP-проверок**. Проверены состав JAR, наличие Filter в Tomcat и отсутствие второй копии API. Проверка PostgreSQL, приведённая ниже, относится к предыдущему запуску; при этой правке Maven-конфигурации она не повторялась. Точное состояние зависимостей на компьютере пользователя не воспроизводилось; после замены POM требуется Maven Reload в IDE.

## Настоящий HTTP и готовая сборка

Проверка выполнена на отдельном локальном порту 8087; стандартный запуск пользователя использует 8080. Вход выполнен с демонстрационными аккаунтами. В отчёты не записывались accessToken или реальные пароли.

Сценарий проверяет health, OpenAPI, вход, профиль, список результатов, PDF результата, PDF сертификата, публичную проверку сертификата, 401 без JWT, 403 для USER в админке, новый экзамен, PUT/GET ответа, save/resume, неизменность deadlineAt, 400 для чужого варианта, 409 для незавершённого PDF, повторный finish, запрет изменения законченного теста, вход администратора, 404 для чужого PDF, выход и недействительность старого JWT.

Подробный список запросов и кодов ответа: examples/smoke-checks.json. Примеры, полученные этим API: examples/demo-result.pdf и examples/demo-certificate.pdf. Результат 38/40=95% является синтетическим, имя в нём «Демо Ученик».

При проверке запуска выявлена и исправлена несовместимая настройка дат Jackson 3. Затем выявлена и исправлена потеря наносекунд при сохранении Instant в TIMESTAMP(6); для начала, дедлайна, сохранения и завершения используется согласованная микросекундная точность. Проверка настоящего JAR добавлена в CI, чтобы проверять основной application.properties, а не только тестовую конфигурацию.

- Windows/macOS: команды запуска подготовлены, исполнение Java-приложения проверено на Linux. Для Windows используется стандартный java -jar через run-demo.cmd.
- Публичное размещение, HTTPS, SMS и email: внешние сервисы не подключались.
