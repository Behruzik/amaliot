# Как проверить проект через Swagger

## 1. Запустить и открыть API

В готовом архиве можно просто запустить **run-demo.cmd** (Windows) или `./run-demo.sh` (Linux/macOS). Требуется Java 17+. Они используют приложенный `dist/Amaliyot.jar`.

В папке с `pom.xml` выполните в PowerShell:

```powershell
.\mvnw.cmd "-Dspring-boot.run.profiles=demo" spring-boot:run
```

На Linux/macOS: `./mvnw -Dspring-boot.run.profiles=demo spring-boot:run`.

Откройте <http://localhost:8080/swagger-ui.html>. Для каждого запроса: раскройте строку -> **Try it out** -> заполните поля -> **Execute**. Смотрите **Server response**, код ответа и **Response body**. Раздел **Example Value** показывает образец, а не реальный ответ сервера.

При занятом порте 8080 используйте `"-Dspring-boot.run.arguments=--server.port=8081"`; затем открывайте порт 8081. Не запускайте две копии обычного файлового H2-проекта одновременно.

## 2. Войти и настроить Authorize

Найдите `POST /api/auth/login`, выберите пример `demoUser` или вставьте:

```json
{
  "email": "student.demo@gmail.com",
  "password": "DemoUser123!"
}
```

Ожидается **200**. Скопируйте строку `accessToken` **без кавычек**. Нажмите **Authorize** вверху, вставьте только эту строку, затем Authorize -> Close. Не добавляйте слово `Bearer`: Swagger делает это сам.

Проверьте `GET /api/profile`: должны вернуться email ученика и роль `USER`. Скопируйте `professionId` - он нужен как `categoryId` при запуске экзамена. Демо-профиль уже заполнен.

Swagger не сохраняет авторизацию после закрытия/обновления страницы. После перезапуска демо получите новый токен.

## 3. Самое полезное сначала: готовый результат и PDF

В demo уже создан завершённый тест: **38 правильных ответов из 40, 95%**. Это синтетические данные для проверки.

1. `GET /api/tests/results`: оставьте `page=0`, `size=20`, выполните запрос.
2. В реальном ответе найдите `content[0].id`. Это ID попытки.
3. `GET /api/tests/results/{attemptId}`: подставьте ID. Сравните `correctAnswers`, `totalQuestions`, `score`, `status`.
4. `GET /api/tests/results/{attemptId}/pdf`: тот же ID, `download=false` или `true`.
5. Ожидается **200**, тип `application/pdf`. Нажмите **Download file** и откройте документ в браузере/просмотрщике PDF.

`download=false` задаёт заголовок inline для клиента; `download=true` - attachment. Сам Swagger обычно предлагает скачать бинарный ответ. Проверьте читаемость имени, направления, 95%, дат и часового пояса.

**Не вставляйте защищённый PDF-адрес в новую вкладку без авторизации:** адресная строка не добавляет `Authorization`. Получить 401 в таком случае правильно. Используйте Swagger или запрос клиента с Bearer JWT.

### Сертификат

1. `GET /api/certificates` -> возьмите настоящий `certificateNumber`, начинающийся с `GEA-`.
2. `GET /api/certificates/{certificateNumber}/pdf` -> **200**, PDF сертификата.
3. `GET /api/certificates/verify/{certificateNumber}` -> публичная проверка. JWT не нужен; `valid=true` для действующего сертификата.

Публичная проверка показывает сведения о сертификате по его номеру. Скачивание PDF защищено и доступно владельцу.

## 4. Пройти новый экзамен

### Начать

В `POST /api/tests/categories/{categoryId}/attempts` вставьте `professionId` из вашего профиля. Ожидается **200**, статус `IN_PROGRESS`, 40 вопросов.

Сохраните из ответа:

- верхний `id` - `attemptId`;
- `deadlineAt` - крайний срок;
- `questions[].id` - ID вопроса **данной попытки**;
- `questions[].options[].id` - ID вариантов **данной попытки**.

ID из админского банка вопросов сюда не подходят: для экзамена создаются отдельные снимки. До завершения API ученика не возвращает флаг правильности вариантов или числовой эталон.

### Ответить

Используйте `PUT /api/tests/attempts/{attemptId}/questions/{questionId}/answer`.

Для `SINGLE` передайте один реальный ID варианта. Например, **только если API вернул ID 123**:

```json
{"selectedOptionIds": [123]}
```

Для `MULTIPLE` передайте все выбранные ID. Для `NUMERIC` передайте число:

```json
{"numericValue": 12.5}
```

Число `12.5` - пример формата; ответ должен соответствовать вашему вопросу. Не передавайте одновременно числовое значение и варианты. Правильный ответ для MULTIPLE требует точного совпадения множества выбранных вариантов.

Очистка ответа SINGLE/MULTIPLE:

```json
{"selectedOptionIds": []}
```

Очистка NUMERIC:

```json
{"numericValue": null}
```

Ожидается **200**. Проверьте `GET /api/tests/attempts/{attemptId}`: выбранный вариант или число должны сохраниться после отдельного запроса.

### Сохранить и продолжить

1. `POST /api/tests/attempts/{attemptId}/save`.
2. `GET /api/tests/attempts/saved` - попытка должна быть в списке доступных для продолжения.
3. `POST /api/tests/attempts/{attemptId}/resume`.
4. Сравните ответы и `deadlineAt` с предыдущим ответом.

**Таймер не останавливается и не продлевается.** Сам ответ сохраняется при каждом PUT, а save добавляет отметку для продолжения.

### Завершить

Выполните `POST /api/tests/attempts/{attemptId}/finish`. Сервер вычислит результат. Незаполненные ответы считаются неправильными. Статус `PENDING` означает завершённый результат, ожидающий административной проверки; PDF уже доступен.

Повторите finish - баллы и время завершения должны остаться теми же. Теперь проверьте JSON результата, PDF и список сертификатов. Сертификат выдаётся при **35+ из 40** без просрочки. В demo задержка пересдачи равна нулю; у обычных направлений действуют их настройки.

## 5. Проверки, которые действительно выявляют ошибки

| Проверка | Что сделать | Ожидаемый результат |
| --- | --- | --- |
| Авторизация | Удалить токен через Authorize -> Logout, вызвать профиль/PDF | 401, JSON UNAUTHORIZED |
| Роли | Под учеником вызвать GET /api/admin/dashboard | 403, а не 500 |
| Владелец | Под другим аккаунтом запросить PDF ученика | 404; документ не раскрывается |
| Незавершённый тест | Запустить новую попытку и запросить её PDF до finish | 409, JSON ATTEMPT_NOT_FINISHED |
| Чужой вариант | Вставить ID варианта другого вопроса | 400 INVALID_OPTION |
| Тип ответа | Для SINGLE передать два варианта или numericValue | 400 |
| Числовые пределы | Для NUMERIC передать 1e20 или больше 6 дробных разрядов | 400 |
| Сохранение | PUT answer -> отдельный GET attempt | Выбранный ответ сохранён |
| Повторное завершение | Дважды вызвать finish | Тот же итог |
| Ответ после завершения | PUT answer после finish | 409 ATTEMPT_NOT_ACTIVE |
| Выход | POST /api/auth/logout, затем профиль со старым токеном | 401 |
| Ограничение auth | Более 20 auth-запросов с одного IP за 60 секунд | 429 AUTH_RATE_LIMITED и Retry-After |

Проверку лимита делайте в конце демонстрации, чтобы не мешать дальнейшему входу. Пять неудачных входов по одному логину включают также отдельную блокировку этого логина на 15 минут. Для дальнейших проверок можно перезапустить одноразовое demo; его данные будут созданы заново.

Не пытайтесь сократить дедлайн подменой клиентского времени: срок проверяет сервер. В автоматических тестах есть проверка истечения срока, сохранения EXPIRED при ответе 409 и пересдачи.

## 6. Администратор

В `POST /api/auth/login` выберите `demoAdmin`:

```json
{
  "email": "admin.demo@example.test",
  "password": "DemoAdmin123!"
}
```

Замените текущий токен в Authorize. Проверьте:

- `GET /api/admin/dashboard` - 200 и статистика.
- `GET /api/admin/questions` с ID демо-категории - банк вопросов и их типы.
- `GET /api/admin/attempts` - список результатов.
- `GET /api/admin/attempts/{id}` - подробная проверка попытки.

Для проверки отзыва сертификата можно отменить **демонстрационную** завершённую попытку через `POST /api/admin/attempts/{id}/cancel`. Публичная проверка номера после этого должна показывать `valid=false`; в PDF владельца появится отметка отзыва. Это изменение состояния: используйте его только на демоданных или осознанно на выбранной попытке.

Приватные PDF-маршруты всегда проверяют владельца. Роль SUPER_ADMIN сама по себе не открывает чужой PDF через пользовательский маршрут; для просмотра администратору служит `/api/admin/attempts/{id}`.

## 7. Если нужен новый пользователь

`POST /api/auth/register` требует уникальные `@gmail.com` email и телефон, пароль минимум 6 символов и `offerAccepted=true`. После регистрации токен возвращается сразу. Затем заполните профиль через `PATCH /api/profile`.

Профессию выберите из `GET /api/professions`. Название региона берите из `GET /api/locations/regions`; название района - из `GET /api/locations/regions/{regionId}/districts`. Передавайте **названия** в `region`/`district`, ID профессии в `professionId`. Для демо-каталога есть `Demo region` и `Demo district`.

Если направление не содержит 40 активных вопросов, API вернёт 409 QUESTION_BANK_INSUFFICIENT. В demo выбирайте направление с названием, начинающимся с «Демо:»; остальные стартовые профессии не наполнены экзаменационными вопросами.

## 8. Проверка одной командой

При запущенном demo и наличии Python 3:

```powershell
python scripts/smoke_demo.py
```

Скрипт обращается только к localhost, выполняет вход, PDF, сертификат, роли, новый экзамен, сохранение/продолжение, отрицательные сценарии и выход. Он создаёт дополнительную демопопытку и сохраняет PDF/OpenAPI в `docs/examples/`. JWT в файлы и вывод не записываются.

Основной набор Java-проверок:

```powershell
.\mvnw.cmd clean verify
```

Фактические выполненные проверки этой версии перечислены в [VERIFICATION.md](VERIFICATION.md).
